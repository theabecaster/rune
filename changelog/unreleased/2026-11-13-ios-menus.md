- **iOS: an App's menu items work.** `App::menu_item` and `AppHandle::set_menu` no longer answer Unsupported on iOS. On an iPad, in an app `rune::run` or `App::run` started, the items join UIKit's main menu (the menu bar and the list a held ⌘ shows): app-menu items follow About, an item in a menu named File, Edit, Format, View, Window or Help goes at the end of that system menu, any other name gets a menu of its own before Window, and separators become sections. An item with a shortcut is a key command there, with two exceptions: a `keys_first` item shows no shortcut and runs when no handler takes its key, and an item whose key UIKit has no name for (Insert, F13 and up) is in the menu with no shortcut, and its chord does nothing there. On an iPhone, which has no main menu, every item's shortcut runs it when no handler takes the key. A view from `rune::ios::view` in another app gets no place in that app's main menu, which its own delegate builds: on an iPhone the shortcuts work as in a Rune app, and on an iPad only a `keys_first` item's does. Dock items and anchors on AppKit actions have no place on iOS.
