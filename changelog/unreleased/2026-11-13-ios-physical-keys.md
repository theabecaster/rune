- **iOS: a hardware keyboard's keys are physical keys too.** Each press and release reaches the runtime as the `PhysicalKeyCode` its USB HID usage names, with the logical key as what happens when no handler takes it, as a desktop window sends them: `El::on_physical_input` on the focused element hears every key (games, WASD), `Tx::physical_key` and `Tx::key_base` are set, and `on_key_up` hears releases. While the keyboard is composing in a text field (marked text is open), a press goes to UIKit alone and only its release reaches the runtime. A character UIKit types into a field reaches the handler as an observation; returning true from it does not stop the character, which UIKit has already typed.
